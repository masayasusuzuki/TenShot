# Claude Code × Xcode でmacOSアプリを作ってApp Storeに出すまで
〜 コーディング中の「あったらいいな」から生まれた10Shot 〜

---

## 1. なぜ作ったのか

きっかけはWindowsの「クリップボード履歴」機能でした。

Windowsには `Win + V` で過去にコピーした内容を一覧表示できる機能がデフォルトで搭載されています。テキストだけでなく画像も複数枚さかのぼれて、選んで貼り付けるだけ。地味ですが、一度使うと手放せない便利さです。

Macに乗り換えたとき、同じことができないことに気づきました。

Claude Codeで開発をしていると、参考画像やスクリーンショットを何枚も見比べながら作業することが多いです。デザインの確認、エラー画面のキャプチャ、Figmaのスクショ……。そのたびにFinderを開いたり、ブラウザのタブを切り替えたりするのが、地味にストレスでした。

「Windowsみたいに、スクショを何枚かストックしておいてサッと見られるアプリがMacにもあれば」

既存アプリも探しましたが、ちょうどいいものが見当たりませんでした。ならば作ろう。そう思い立ったのが、10Shot の始まりです。

---

## 2. 要件定義：「こんなのがあったらいいな」から始める

最初から完璧な仕様書は必要ありません。
「こんなのがあったらいいな」レベルの言葉を並べるだけで十分です。

```
- メニューバーに常駐してほしい
- スクショを最大10枚くらいストックできればいい
- クリックひとつでコピーできれば最高
- 暗めのデザインで、画面に馴染んでほしい
- 透過できれば他のウィンドウの邪魔にならない
- シンプルでいい。機能は少なくていい
```

これをそのままClaude Codeに投げます。
「要件定義書を書いてください」などと言わなくて大丈夫です。
ざっくりした言葉で十分伝わります。

---

## 3. 開発環境の準備

必要なものはシンプルです。

- Claude Code（CLIをインストール、Maxプランがおすすめ）
- Xcode（Mac App Storeから無料でインストール）
- ターミナル（最初からMacに入っています）

Xcodeを開いて「macOS App」で新規プロジェクトを作成します。
言語はSwift、UIフレームワークはAppKit（メニューバーアプリはAppKitが扱いやすいです）。

あとはプロジェクトのディレクトリでClaude Codeを起動するだけです。

```bash
cd ~/Desktop/application/TenShot
claude
```

---

## 4. Claude Code との開発フロー

基本的なサイクルはこうです。

1. やりたいことを日本語で伝える
2. Claude Codeがコードを書いてくれる
3. ビルドして動作確認
4. フィードバックして繰り返す

たとえば最初のプロンプトはこんな感じです。

```
メニューバーに常駐するmacOSアプリを作りたい。
左クリックでパネルが開いて、スクリーンショットや
ドロップした画像を最大10枚ストックできる。
コピーボタンでクリップボードに送れる。
ダークなグラスモーフィズムデザインにしたい。
```

これだけで、Claude Codeは必要なファイルを一気に生成してくれます。
`AppDelegate.swift`、`PanelViewController.swift`、`ImageStore.swift`……。

人間が書くより圧倒的に速いです。

---

## 5. 最大の壁：「人間経由」がボトルネックになる

開発が進むと、必ずXcodeの設定まわりで詰まります。

- App Sandboxの有効化
- entitlementsファイルの設定
- Signing & Capabilitiesのチーム設定
- Info.plistへの権限追加

こういった設定はコードではなく、XcodeのGUI上でポチポチやる作業です。

最初はこんなフローになっていました。

```
Claude Code「Signing & Capabilitiesを開いて、
App Sandboxにチェックを入れてください」

→ 自分がXcodeを操作

→ 「できました。次はどうしますか？」

→ Claude Code「次はentitlementsに〜を追加して…」

→ また自分がXcodeを操作

→ 繰り返し……
```

自分がClaude Codeの「手」になっている状態です。
アドバイスを受けて→操作して→報告して→また受けて……このループが延々と続きます。

これが思った以上にタイムロスでした。

---

## 6. ブレークスルー：Claude Codeにファイルを直接触らせる

解決策はシンプルでした。

Claude Codeにターミナル経由でXcodeのプロジェクトファイルを直接読ませて、編集させることです。

Xcodeのプロジェクト設定は、実態はただのテキストファイルです。

```
TenShot.xcodeproj/project.pbxproj  ← ビルド設定・ファイル参照がすべて入っている
TenShot/TenShot.entitlements       ← 権限設定
TenShot/Info.plist                 ← アプリ情報
```

Claude Codeはこれらのファイルをターミナルから読むことができます。
中身を把握した上で、そのまま編集まで行えます。

```bash
# Claude Codeが実際にやっていること
cat TenShot.xcodeproj/project.pbxproj  # 中身を読む
# → 問題箇所を特定
# → ファイルを直接編集
```

自分がXcodeのGUIを操作する必要がなくなりました。
「ここを直してください」と伝えれば、Claude Codeが直接ファイルを書き換えてくれます。

Xcodeでプロジェクトを再度開くと、設定が反映されています。

人間が仲介する部分を排除したら、開発速度が一気に上がりました。

---

## 7. できあがったもの

こうして生まれたのが 10Shot です。

主な機能：
- メニューバーに常駐（左クリックでパネル開閉、右クリックで終了）
- スクリーンショット範囲選択（SSボタン一発）
- 画像のドラッグ＆ドロップ対応
- ワンクリックでクリップボードにコピー
- 透過スライダー（他のウィンドウと重ねて使えます）
- グラスモーフィズムのダークUI

最大10枚までストック。コーディング中に参考画像を手元に置いておくのに最適です。

## 8. Mac App Store への申請

アプリが完成したら、次はApp Storeへの申請です。

### Apple Developer Programへの登録

まず年会費 12,980円（税込）を払って開発者登録をします。
これがないとApp Storeに出せません。

`https://developer.apple.com/programs/enroll/`

### Xcodeでアーカイブ

```
Xcode → Product → Archive
```

ビルドが通ったらOrganizerが開きます。

### App Store Connectにアップロード

```
Organizer → Distribute App → App Store Connect → Upload
```

### 申請情報の入力

App Store Connectで以下を用意します。

- スクリーンショット（1280×800 または 1440×900）
- アプリの説明文・キーワード
- プライバシーポリシーURL（必須）
- サポートURL

「審査へ提出」を押したら、あとは待つだけです。通常1〜3営業日で審査結果が届きます。

## 9. まとめ：Claude Code × Xcodeで気づいたこと

「人間が仲介する部分を減らすほど、開発が速くなる」

これが今回の一番の学びです。

Claude Codeは賢いです。でも、人間がフィルターになると途端に遅くなります。
「アドバイスを受けて→自分が操作して→報告する」ループは思った以上にコストが高いです。

Claude Codeにできることは、なるべくClaude Codeにやらせましょう。
`.pbxproj` でも `entitlements` でも、テキストファイルならターミナルから直接触れます。

アイデアを思いついた日に、App Store申請まで一人で完走できる時代になりました。

コードが書けなくても大丈夫です。「こんなのがあったらいいな」という言葉があれば、それが出発点になります。
